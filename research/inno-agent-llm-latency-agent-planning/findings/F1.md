# F1: End-to-End Latency Pipeline Breakdown

## Findings

### [1] GitHub webhook delivery is bounded by a 10-second server response timeout
- quote: "Your server should respond with a 2XX response within 10 seconds of receiving a webhook delivery. If your server takes longer than that to respond, then GitHub terminates the connection and considers the delivery a failure."
- url: https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks
- source_type: primary
- published: 2024
- confidence: high

### [2] GitHub recommends async queue architecture for webhook ingestion to avoid 10s timeout
- quote: "In order to respond in a timely manner, you may want to set up a queue to process webhook payloads asynchronously. Your server can respond when it receives the webhook, and then process the payload in the background without blocking future webhook deliveries."
- url: https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks
- source_type: primary
- published: 2024
- confidence: high

### [3] GitHub webhook payloads are capped at 25 MB, impacting large PR reviews
- quote: "Payloads are capped at 25 MB. If an event generates a larger payload, GitHub will not deliver a payload for that webhook event."
- url: https://docs.github.com/en/webhooks/webhook-events-and-payloads
- source_type: primary
- published: 2024
- confidence: high

### [4] GitHub secondary rate limits cap at 80 content-generating requests/minute, blocking PR comment posting under load
- quote: "In general, no more than 80 content-generating requests per minute and no more than 500 content-generating requests per hour are allowed."
- url: https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api
- source_type: primary
- published: 2024
- confidence: high

### [5] Ollama tool calling requires multiple sequential LLM round-trips, each incurring full prefill + decode latency
- quote: "An agent loop allows the model to decide when to invoke tools and incorporate their results into its replies. ... while True: response = chat(model='qwen3', messages=messages, tools=[add, multiply]); messages.append(response.message); if response.message.tool_calls: ... messages.append({...tool result...}); else: break"
- url: https://docs.ollama.com/capabilities/tool-calling.md
- source_type: primary
- published: 2025
- confidence: high

### [6] Ollama default context window is 4096 tokens; larger contexts increase prefill latency proportionally
- quote: "By default, Ollama uses a context window size of 4096 tokens. This can be overridden with the OLLAMA_CONTEXT_LENGTH environment variable."
- url: https://docs.ollama.com/faq.md
- source_type: primary
- published: 2025
- confidence: high

### [7] Ollama models unload from memory after 5 minutes by default, causing cold-start latency on idle intervals
- quote: "By default models are kept in memory for 5 minutes before being unloaded. This allows for quicker response times if you're making numerous requests to the LLM."
- url: https://docs.ollama.com/faq.md
- source_type: primary
- published: 2025
- confidence: high

### [8] Ollama parallel requests multiply memory usage linearly via context expansion
- quote: "Parallel request processing for a given model results in increasing the context size by the number of parallel requests. For example, a 2K context with 4 parallel requests will result in an 8K context and additional memory allocation."
- url: https://docs.ollama.com/faq.md
- source_type: primary
- published: 2025
- confidence: high

### [9] Ollama queues up to 512 requests before rejecting with 503, creating hidden tail latency
- quote: "The following server settings may be used to adjust how Ollama handles concurrent requests on most platforms: OLLAMA_MAX_QUEUE — The maximum number of requests Ollama will queue when busy before rejecting additional requests. The default is 512."
- url: https://docs.ollama.com/faq.md
- source_type: primary
- published: 2025
- confidence: high

### [10] Ollama streaming emits NDJSON chunks at ~10ms intervals, contributing to perceived first-token latency
- quote: "{\"model\":\"gemma4\",\"created_at\":\"2025-10-26T17:15:24.097767Z\",\"response\":\"That\",\"done\":false}\n{\"model\":\"gemma4\",\"created_at\":\"2025-10-26T17:15:24.109172Z\",\"response\":\"'\",\"done\":false}"
- url: https://docs.ollama.com/api/streaming.md
- source_type: primary
- published: 2025
- confidence: high
