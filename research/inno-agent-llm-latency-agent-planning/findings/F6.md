# F6: Agent Planning in Production Systems

## Findings

### [1] OpenHands uses a TaskToolSet for sub-agent delegation with synchronous blocking and resumable task IDs
- quote: "The TaskToolSet lets a parent agent launch sub-agents that handle complex, multi-step tasks autonomously. Each sub-agent runs synchronously — the parent blocks until the sub-agent finishes and returns its result."
- url: https://docs.openhands.dev/sdk/guides/task-tool-set.md
- source_type: primary
- published: 2025
- confidence: high

### [2] OpenHands Goal Completion Loop uses a separate judge LLM to verify task completion before stopping
- quote: "A plain `conversation.run()` stops as soon as the agent thinks it is done. The `/goal` command is stricter: after each run it asks a second judge LLM to audit the transcript for authoritative evidence — file contents, command output, test results — that the objective is provably complete."
- url: https://docs.openhands.dev/sdk/guides/convo-goal.md
- source_type: primary
- published: 2025
- confidence: high

### [3] Claude Code has a dedicated Plan subagent that runs read-only before presenting an execution plan
- quote: "Plan — A research agent used during plan mode to gather context before presenting a plan. When you're in plan mode and Claude needs to understand your codebase, it delegates research to the Plan subagent so that exploration output stays in a separate context window."
- url: https://code.claude.com/docs/en/sub-agents
- source_type: primary
- published: 2025
- confidence: high

### [4] Claude Code Dynamic Workflows orchestrate dozens to hundreds of subagents from a JavaScript script with phase-based execution
- quote: "A dynamic workflow is a JavaScript script that orchestrates subagents at scale. Claude writes the script for the task you describe, and a runtime executes it in the background while your session stays responsive."
- url: https://code.claude.com/docs/en/workflows
- source_type: primary
- published: 2025
- confidence: high

### [5] Claude Code Workflows are resumable within a session — completed agents return cached results on resume
- quote: "If you stop a run, you can resume it: agents that already completed return their cached results, and the rest run live. An agent that was still running when you stopped isn't saved and starts over on resume."
- url: https://code.claude.com/docs/en/workflows
- source_type: primary
- published: 2025
- confidence: high

### [6] OpenAI Codex runs each task in an isolated cloud sandbox, executing iteratively until tests pass, with AGENTS.md for project-specific guidance
- quote: "Each task is processed independently in a separate, isolated environment preloaded with your codebase. Codex can read and edit files, as well as run commands including test harnesses, linters, and type checkers. Task completion typically takes between 1 and 30 minutes."
- url: https://openai.com/index/introducing-codex/
- source_type: primary
- published: 2025-05-16
- confidence: high

### [7] Codex (codex-1) was trained via reinforcement learning on real-world coding tasks to iteratively run tests until passing
- quote: "Codex is powered by codex-1, a version of OpenAI o3 optimized for software engineering. It was trained using reinforcement learning on real-world coding tasks in a variety of environments to generate code that closely mirrors human style and PR preferences, adheres precisely to instructions, and can iteratively run tests until it receives a passing result."
- url: https://openai.com/index/introducing-codex/
- source_type: primary
- published: 2025-05-16
- confidence: high

### [8] Cline uses an explicit Plan/Act mode toggle — Plan mode explores and lays out strategy, Act mode executes with human approval per action
- quote: "Toggle between Plan mode and Act mode. In Plan mode, Cline explores your codebase, asks clarifying questions, and lays out a strategy. Once you're aligned, switch to Act mode and Cline executes the plan. Every file edit and terminal command requires your approval."
- url: https://github.com/cline/cline
- source_type: primary
- published: 2025
- confidence: high

### [9] Cline Kanban enables parallel multi-agent execution with per-card worktrees, auto-commit, and dependency chains
- quote: "Run many agents in parallel from a web-based task board. Each card gets its own worktree, auto-commit, and dependency chains."
- url: https://github.com/cline/cline
- source_type: primary
- published: 2025
- confidence: high

### [10] Roo Code Orchestrator Mode (Boomerang Mode) delegates complex tasks to specialized modes using a new_task tool
- quote: "A strategic workflow orchestrator (aka Boomerang Mode) that breaks down complex tasks and delegates them to specialized modes. Uses the new_task tool to delegate subtasks to other modes."
- url: https://roocodeinc.github.io/Roo-Code/basic-usage/using-modes
- source_type: primary
- published: 2025
- confidence: high

### [11] Claude Code subagents support worktree isolation for parallel independent edits without conflicts
- quote: "A subagent with `isolation: worktree` runs its Bash and PowerShell commands inside its worktree. A command whose working directory resolves to your main checkout instead... fails with an error."
- url: https://code.claude.com/docs/en/sub-agents
- source_type: primary
- published: 2025
- confidence: high

### [12] Goose is a general-purpose extensible agent with MCP-based tool integration and session persistence
- quote: "goose is a general-purpose AI agent that runs on your machine. Not just for code — use it for research, writing, automation, data analysis, or anything you need to get done."
- url: https://github.com/aaif-goose/goose
- source_type: primary
- published: 2025
- confidence: medium
